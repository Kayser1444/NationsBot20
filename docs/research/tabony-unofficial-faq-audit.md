# Tabony implementation versus Logitude's unofficial FAQ

> Correction after discussion of the FAQ: the replacement-timing observation below is **not a confirmed defect**. Removing the old card's stability before adding the new card's stability, with a most/least check between them, is consistent with the replacing-cards clarification and the general continuous-check rule. Worker return correctly suppresses the intermediate check. The Vesuvius end-of-age observation has no demonstrated gameplay consequence. The only confirmed, unambiguous discrepancy from this unofficial-FAQ audit is Galileo bypassing Axumite's surcharge. The original detailed observations below are retained as investigation history; this correction supersedes their stronger defect classifications.

Audited 2026-10-17. **The implementation does not honor every entry without qualification.** The clearest direct conflict is Galileo's free purchase bypassing the Axumite surcharge. Replacement and end-of-age processing also expose intermediate most/least checks. Versailles and Sheba follow the main ruling while retained, but their effects end on replacement.

## Scope and evidence

The baseline is all 28 entries in `data/question/inofficial-faq-amendments.json`, checked against [Logitude's original BGG post, Nations FAQ += 2](https://boardgamegeek.com/thread/3605801/article/46844956#46844956). The original post presents answers from Rustan and Robert rewritten by Charles/Logitude. These are unofficial clarifications, not published official errata. The original page was visually inspected to verify that the local headings and substance match all 28 entries in the original post.

The implementation is `Logitude/nations` at immutable commit [`9c344205b1802c9583d20c749b89a4cfa52516f7`](https://github.com/Logitude/nations/commit/9c344205b1802c9583d20c749b89a4cfa52516f7), from `data/question/tabony-snapshot.json`. Independent verification confirmed this was GitHub HEAD on the audit date and matched all 20 snapshot files to live Git blob hashes. **The revision actually deployed at games.tabony.net was not verified.** Findings apply to this source revision.

Evidence combines source tracing and seven focused offline component probes in [probe_tabony_faq.py](probe_tabony_faq.py). The script verifies every snapshot file's SHA-256 before extracting it into a temporary directory inside `.tmp`, imports the real implementation, and uses minimal fixtures without network calls. These are not full-game replay tests. A supported verdict means the relevant code path implements the ruling; it does not claim exhaustive testing of every possible game interaction.

The replacement-lifetime exceptions are also explicitly acknowledged by Logitude in the [known implementation differences](https://games.tabony.net/forum/viewtopic.php?p=4#p4), whose original page was independently inspected on the audit date. They are intentional documented differences, rather than newly discovered regressions.

## Findings requiring attention

### Axumite surcharge disappears for Galileo

`GalileoGalilei.activate` delegates to `player.buy_action(choice, free=True)`. In that method, the `free` branch sets the price to zero and skips the whole block computing and making `extra payment`. `can_buy_card(..., free=True)` also skips affordability checks for the surcharge. The Axumite marker is subsequently removed by the normal `buying card` hook. Thus a marked card can be bought without paying Axumite, even when the buyer has no gold. New Kingdom's ordinary discount correctly leaves the surcharge intact. [Galileo](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/progress_cards.py#L2486-L2504), [purchase path](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/player.py#L499-L555), [availability path](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/player.py#L258-L266).

Probe: a free marked purchase leaves the buyer's 3 gold untouched and gives Axumite's owner zero; expected buyer 0, owner 3. This calls Galileo.activate with an eligible marked Himeji Castle through the real buy_actions selector.

### Replacement is not atomic for existing conditional cards

`place_card` calls `remove(old_card)` before inserting the new card and adding its immediate values. `remove_cards` unconditionally recalculates most/least at its end. A second recalculation follows placement. This correctly subtracts old military/stability before adding new values, but also exposes a transient state to existing Qin Shi Huang and similar cards. [Placement](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/player.py#L394-L415), [removal](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/player.py#L868-L902), [Qin](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/progress_cards.py#L2211-L2225).

Probe: with two advisor slots, existing Qin and a +1 stability advisor, a replacement with another +1 stability advisor causes stability `1 → 0 → 1`; the opponent is at 0. Qin is removed during the temporary tie, although the final board is not least stable. The focused fixture replaces Saint Augustine with Thomas Aquino, distinct advisors each providing +1 stability, with Qin in a second advisor slot. It is a component demonstration of the update boundary, not a full-game replay.

**Limit:** this is not a reproduced failure of the original exact Genghis-to-newly-bought-Qin example. An incoming Qin registers its conditional removal only in `placed`, after old-card removal, so that example has the desired protection. The named Genghis/Qin interaction is classified as supported; the broader existing-Qin problem is an additional finding.

### End-of-age callbacks can defeat the deferred check

The outer resolution phase defers its explicit most/least check until after the complete end-of-age loop. However, Vesuvius calls `player.return_worker()`, which recalculates most/least immediately, before other players' end-of-age effects finish. Thus the complete stated sequence is not guaranteed despite the outer loop matching it. This is a source-confirmed timing gap, without a full-game outcome reproduction. [Resolution](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/match.py#L640-L657), [Vesuvius](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/progress_cards.py#L3124-L3137), [return-worker update](https://github.com/Logitude/nations/blob/9c344205b1802c9583d20c749b89a4cfa52516f7/player.py#L832-L864).

## Reproduction results

Run `python docs/research/probe_tabony_faq.py` using a working Python 3 installation. The audited run completed successfully with these observations:

```text
FAIL Axumite/free purchase: buyer retains 3 gold; Axumite owner receives 0 (FAQ expects 0/3).
FAIL replacement atomicity: existing Qin removed during 1 -> 0 -> 1 stability replacement.
PASS incoming Qin: replacing Genghis restores stability before Qin registers its condition.
QUALIFICATION Versailles: forced least stability ends immediately when card is removed.
QUALIFICATION Sheba: no-upkeep effect ends immediately when dynasty is removed.
PASS Coffee House: no immediate books; two workers produce 8 books with Chopin.
PASS immediate self-removal: bought Hypatia leaves advisor slot empty.
Snapshot: 9c344205b1802c9583d20c749b89a4cfa52516f7
```

`FAIL` labels denote observed disagreement with the target behavior; the script intentionally asserts the observed source behavior so it remains a reproducible diagnostic. Exit success means the observations reproduced, not that the implementation passed the FAQ.

Potential fixes should preserve independent surcharge affordability/payment for free card purchases, defer most/least recalculation across full card replacement, and defer nested checks across end-of-age batches. Versailles/Sheba lifetime changes require deciding which source interpretation the project intends to follow. No gameplay implementation was changed in this audit.

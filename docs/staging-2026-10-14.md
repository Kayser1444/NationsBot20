# Samlad stagingkandidat - 14 oktober 2026

Utgångspunkt är produktionscommit `c8159a9`. Kandidaten samlar det lokala arbetet från chattarna om säkerhet, DM-påminnelser, fler communities, serverbelastning, testmiljö och kort/FAQ. Den publiceras till den befintliga Railway-tjänsten NationsBot20-Staging via Git-grenen `staging`.

## Beteendeförändringar

| Område | Ändring |
| --- | --- |
| Inloggning | Begränsning per klient, begränsat antal väntande OAuth-flöden och en minnesbegränsad cache. En fylld cache blockerar inte alla nya inloggningar. |
| Kommandon | Ändringar begränsas per användare; kontroll-DM har separat väntetid. Samma redan bekräftade tur påminns inte igen efter off/on eller omstart. |
| Speldata | Felaktigt formade WebSocket-svar ignoreras utan att krascha bevakningen eller ersätta den senaste giltiga spelställningen. |
| DM-påminnelser | Mottagarens mention tas bort från DM-texten och inga mentions tillåts i DM-payloaden. Kanalpåminnelser behåller sin avsedda mention. |
| Flera communities | Kommandon fungerar i alla kanaler på servrar där boten finns. Nya communities behöver inga egna inställningar och använder DM-påminnelser. |
| SM-undantag | Kanalpåminnelser kan bara väljas i den konfigurerade SM-påminnelsekanalen. DM-kommandon kräver medlemskap i minst en server där boten finns. Prenumerationen följer Discord-användaren. |
| Belastning | Schemalagda fullständiga spelavläsningar går från var 20:e sekund till var femte minut. Draguppdateringar kommer fortfarande direkt. Tysta anslutningar återansluts efter cirka 10-15 minuter. |
| Kortkommando | `/card` med namnförslag, Tabony-bild, kompakt metadata och lokal FAQ-bank. Piloturvalet är Porcelain Tower: 13 sammanfattade punkter från tio källkontrollerade poster. |
| FAQ-gränssnitt | FAQ börjar hopfälld. Visa/Dölj och vid behov sidknappar uppdaterar samma meddelande. Kortbilden ligger kvar; inga spoiler-markeringar behövs. |
| Data och granskning | 216 extraherade FAQ-textposter och en preliminär kortkatalog. Övriga 206 poster väntar på innehållsgranskning. Original, sammanfattning, källsida och kortkoppling hålls isär. |
| Drift | Separat lokal dev-konfiguration och dokumenterat arbetsflöde för Railway staging. Dockerbilden innehåller de JSON-filer som körningen behöver. |

## Innehåll i kandidaten

Kod, tester, importerad FAQ-data, granskningsunderlag, importskript och dokumentation ingår i Git-committen. Privata `.env`-filer, prenumerationer, sessionsdata, leveranshistorik, arbetsfiler samt referens-PDF:er och bildarkiv hålls lokala. Dockerbilden kopierar endast körningsfiler och den data som boten använder.

## Gemensamt prov i Discord

1. Kör testbotens `/help`, `/status` och `/language` på testservern och i DM.
2. Kör `/card name:Porcelain Tower`; öppna och stäng FAQ:n och kontrollera att bilden ligger kvar.
3. Prenumerera på ett testnamn och kontrollera att en verklig turpåminnelse kommer i DM utan mention.
4. Kontrollera att `dm:off` avslås utanför den konfigurerade test-/SM-påminnelsekanalen.
5. Prova från en andra server samt från ett konto som endast är medlem där. Public Bot och installationen i Discord behöver tillåta detta.
6. Kontrollera att prenumerationen finns kvar efter en stagingomstart och att samma tur inte skickas om.

Inloggnings- och HTTPS/OAuth-prov mot staging kräver att dess separata ägarkonsol är aktiverad med en stagingdomän och OAuth-konfiguration. Dessa kontroller täcks lokalt av testerna även om stagingens webbkonsol är avstängd.

Om Railway staging fortfarande använder samma testapplikation som lokal dev ska den lokala testboten stoppas före överlämningen. Produktionsbotens miljö och `main` ska inte uppdateras vid denna stagingdriftsättning.
